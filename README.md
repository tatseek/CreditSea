# Credit Sea

Credit Sea is a Flutter loan onboarding and application demo backed by a
Node.js/Express API, MongoDB Atlas, Resend email OTP delivery, and Vercel
serverless hosting.

## Live backend

- API origin: `https://backend-nu-mocha-n1313jnkw2.vercel.app`
- API base URL: `https://backend-nu-mocha-n1313jnkw2.vercel.app/api`
- Health check: `https://backend-nu-mocha-n1313jnkw2.vercel.app/health`

The Flutter app uses the deployed API by default, so a release APK works on a
physical phone without a development computer on the same network.

## Features

- Mobile OTP registration and password-based returning-user sign-in
- Secure JWT persistence using Flutter Secure Storage
- Personal details, income, email OTP, and PAN onboarding
- Loan calculator and server-side eligibility evaluation
- Multiple historical loan applications with one active application at a time
- Offer acceptance, cancellation, and application-status history
- Responsive Flutter UI based on the supplied CreditSea designs
- Node.js API with MongoDB persistence and Resend email delivery

## Application flow

```text
Splash
  -> Register or Sign in
  -> Personal details
  -> Email verification
  -> PAN verification
  -> Home
  -> Loan calculator
  -> Offer
  -> Application status
```

Returning users with a valid stored session and completed profile open the home
screen directly. The home screen provides entry points for applying for a loan,
reviewing offers, and tracking applications.

## Test credentials and OTP limitations

### Mobile OTP

The assignment build does not integrate a paid SMS gateway. In development
mode, use:

- Mobile number: `9999999999`
- OTP: `1234`

Other mobile numbers receive a generated OTP only in the API response/log while
`OTP_MODE=development`. A production SMS provider must replace this development
branch before real phone delivery is possible.

### Email OTP

Email OTPs are generated by the backend and sent through Resend. The current
sender is Resend's test sender (`onboarding@resend.dev`), which is restricted to
the Resend account owner's verified email. For the current deployment, use:

- Supported recipient: `das31arunima@gmail.com`

Sending OTPs to arbitrary Gmail addresses requires verifying a sending domain
in Resend and updating `EMAIL_FROM` to an address on that domain. Email OTPs are
six digits, expire after the configured TTL, are stored only as bcrypt hashes,
and allow at most five incorrect attempts.

## Run the Flutter app

```sh
flutter pub get
flutter run
```

The deployed API is the default. To use a local backend, override it at build
time:

```sh
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8080/api
```

Use `localhost` instead of `10.0.2.2` for iOS Simulator, desktop, or web when
the API runs on the same computer.

## Run the backend locally

```sh
cd backend
cp .env.example .env
npm install
npm run dev
```

Set `MONGODB_URI`, secrets, and optional Resend configuration in
`backend/.env`. Never commit that file.
